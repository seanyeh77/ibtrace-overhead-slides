# ibtrace 的偵測器

| 偵測器 | 在找什麼 |
| --- | --- |
| 沒綁核 | rank 沒被綁住，常被搬到別的 CPU |
| 跨 NUMA | rank 跑在離網卡很遠的 CPU |
| eager 與 rndv 邊界 | 訊息卡在兩種傳送方式的切換點 |
| 重複登記記憶體 | 同一塊記憶體一再登記與取消 |
| 慢對端 | 某個 rank 總是回應得比較慢 |
| 同機走網卡 | 同台機器的資料繞出網卡傳送 |

::note::
偵測器讀 ibtrace 的紀錄，在計時前寫下預測。

後四個看網路呼叫，是 ibtrace 獨有的。

# 一台機器有 8 個 NUMA node

| 位置 | NUMA node | CPU 編號 | 網卡 |
| --- | --- | --- | --- |
| 第 1 顆 CPU | node 0–3 | 0–55 | 掛在 node 1 |
| 第 2 顆 CPU | node 4–7 | 56–111 | 沒有 |

每個 node 有 14 顆核心，一台共 112 顆。

::note::
NUMA：讀旁邊的記憶體快，讀遠處的慢。

綁核：規定 rank 只能在哪些 CPU 上執行。

# 比較的綁法與落點

| 綁法 | 參數 | 落點 |
| --- | --- | --- |
| 依序綁核 | `cores` | 擠在每顆 CPU 的前幾顆核 |
| 分散到 8 個 node | `map_ldom:0,1,2,3,4,5,6,7` | 平均分到所有 node |
| 網卡側分散 | `map_ldom:0,1,2,3` | 平均分到網卡那顆 CPU |
| 遠端分散 | `map_ldom:4,5,6,7` | 平均分到另一顆 CPU |
| 擠到網卡旁 | 用 taskset 逐 rank 綁 | 幾乎都擠在網卡的 node |

::note::
參數接在 srun --cpu-bind= 後面。

# 第一段 - 8 種設定只有綁核有效

| 設定 | 結果 |
| --- | --- |
| 綁在原地 | 4 個程式有空間 |
| 擠到網卡旁 | 5 個程式都有害 |
| cyclic 分配 | 沒有空間，MG 有害 |
| 關閉同機共享記憶體 | allreduce、alltoall、BT 有害 |
| glibc mmap 門檻 | 5 個程式都沒有差別 |
| glibc trim 門檻 | 5 個程式都沒有差別 |
| rendezvous 門檻 1 KB | 5 個程式都沒有差別 |
| rendezvous 門檻 2 MB | allreduce、alltoall 有害 |

::note::
後五種在綁好的狀態下比較。

# 網路層偵測器 - 結果與收益估計

| 項目 | 結果 |

| 沒綁核偵測器 | 5 個程式觸發，4 個有空間 |

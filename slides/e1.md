# 實驗設計

::note::
兩段都是每台 16 個 rank、同樣 5 個程式：NPB 的 LU、BT、MG，OSU 的 allreduce、alltoall。

收益 ＝ 1 − 改後時間 ÷ 基準時間，正值代表變快。

第一段 11/26，第二段 11/27，第二段 455 次計時，失敗 0 次。

# 一台機器有 8 個 NUMA node

| 位置 | NUMA node | CPU 編號 | 網卡 |
| --- | --- | --- | --- |
| 第 1 顆 CPU | node 0–3 | 0–55 | 掛在 node 1 |
| 第 2 顆 CPU | node 4–7 | 56–111 | 沒有 |

每個 node 有 14 顆核心，一台共 112 顆。

::note::
NUMA：讀自己旁邊的記憶體快，讀遠處的慢。

SNC4：Intel CPU 的設定，把每顆 CPU 切成 4 個 NUMA node。

綁核：規定 rank 只能在哪些 CPU 上執行。

預設不綁，系統可以把 rank 搬走。

# 比較的綁法與落點

| 綁法 | 參數 | 每台 16 個 rank 的落點 |
| --- | --- | --- |
| 天真綁核 | `cores` | node 0 與 node 4 各 8 個 |
| 分散到 8 個 node | `map_ldom:0,1,2,3,4,5,6,7` | 8 個 node 各 2 個 |
| 網卡側分散 | `map_ldom:0,1,2,3` | node 0–3 各 4 個 |
| 遠端分散 | `map_ldom:4,5,6,7` | node 4–7 各 4 個 |
| 擠到網卡旁 | 用 taskset 逐 rank 綁 | node 1 有 14 個，node 2 有 2 個 |

::note::
參數都接在 srun --cpu-bind= 後面。

預設不綁：srun 不加參數。

綁在原地：照觀察到的位置，用 taskset 逐 rank 綁。

map_ldom：每個 rank 綁一整個 node。

落點都經實際取樣確認。

# 不綁核的代價：兩組機器都重現

| 程式 | 第一段 | 第二段 |
| --- | ---: | ---: |
| LU | +0.7 % | +1.3 % |
| BT | +11.6 % | +12.5 % |
| MG | +29.8 % | +37.7 % |
| allreduce | +43.5 % | +46.5 % |
| alltoall | +10.8 % | +10.2 % |

::note::
比較的是綁在原地 vs 預設不綁。

兩段用的是不同的 4 台機器。

LU 兩次都沒有空間。

綁核後，allreduce 的 CV 從 17.5 % 降到 2.2 %。

# 一行參數，就比照 trace 綁得更好

| 程式 | 綁在原地 | 天真綁核 | 分散到 8 個 node |
| --- | ---: | ---: | ---: |
| LU | +1.3 % | −0.2 % | +3.4 % |
| BT | +12.5 % | −0.6 % | +18.6 % |
| MG | +37.7 % | +13.8 % | +60.0 % |
| allreduce | +46.5 % | +11.8 % | +50.2 % |
| alltoall | +10.2 % | +1.3 % | +12.1 % |

::note::
三欄都和預設不綁比較。

天真綁核在 5 個程式都比綁在原地差。

偵測器修正前，建議的正是天真綁核。

# 靠近網卡沒有影響，擠才有

| 程式 | 網卡側 vs 遠端 | 分散 vs 擠到網卡旁 |
| --- | ---: | ---: |
| LU | +0.2 % | +7.9 % |
| BT | 0.0 % | +31.7 % |
| MG | +1.5 % | +63.1 % |
| allreduce | −0.4 % | +69.5 % |
| alltoall | +0.3 % | +22.4 % |

::note::
第一欄只差離網卡遠近，5 個程式都沒有空間。

第二欄都在網卡側，只差分散或擠。

MG 的 +1.5 % 只差計時的一格 0.01 s。

# 收益來自每次迭代，不是固定成本

| 程式 | 每次迭代省下 | 95 % 區間 | 固定成本省下 | 95 % 區間 |
| --- | ---: | ---: | ---: | ---: |
| BT | 0.67 ms | 0.41–0.94 ms | +0.11 s | −0.20 到 +0.43 s |
| MG | 31.8 ms | 25.0–38.7 ms | −0.38 s | −2.46 到 +1.70 s |
| allreduce | 0.47 ms | 0.32–0.62 ms | +0.19 s | −0.82 到 +1.19 s |
| alltoall | 4.18 ms | 3.25–5.11 ms | +0.20 s | −0.25 到 +0.66 s |

::note::
綁在原地 vs 預設不綁，時間是牆鐘。

用長版擬合：時間 ＝ 固定成本 ＋ 每次迭代 × 迭代數。

最長的執行約 30 s。

# 偵測器與收益估計

| 項目 | 結果 |
| --- | --- |
| 沒綁核偵測器 | 5 個程式觸發，4 個有空間 |
| 跨 NUMA 偵測器 | 5 個程式觸發，0 個有空間 |
| 收益估計的盲測 | 5 個程式只有 LU 一致 |

估計只有實測收益的 0.001–0.002 倍。

::note::
沒綁核的效果第一段已看過，只算確認，不算盲測。

跨 NUMA 對應網卡側分散 vs 遠端分散。

估計方法：最慢 rank 排隊等 CPU 的時間比例。

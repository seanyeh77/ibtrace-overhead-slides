# 看過結果後的四項修正

| 修正 | 內容 |
| --- | --- |
| 不綁核的建議 | 拿掉 `--cpu-bind=cores`，改成綁在原地或分散綁核 |
| 跨 NUMA 的建議 | 改標「未驗證」，不再建議集中到網卡旁 |
| 量測區間 | 只量程式自己計時的區段 |
| 收益估計 | 新增排隊等 CPU 的估計 |

::note::
四項都是看過第一段才改的，標為事後修改。

量測區間原本含啟動與結束，是程式錯誤。

# 七種綁法

| 綁法 | 怎麼綁 |
| --- | --- |
| 預設不綁 | 不加任何參數 |
| 綁在原地 | 依觀察到的位置，每個 rank 綁一顆 CPU |
| 天真綁核 | `--cpu-bind=cores` |
| 分散到 8 個 node | `--cpu-bind=map_ldom:0,1,2,3,4,5,6,7` |
| 網卡側分散 | `--cpu-bind=map_ldom:0,1,2,3` |
| 遠端分散 | `--cpu-bind=map_ldom:4,5,6,7` |
| 擠到網卡旁 | 14 個綁在 node 1，2 個綁在 node 2 |

::note::
參數都加在 srun 後面。

map_ldom：每個 rank 綁一整個 NUMA node。

清單用完就從頭再用。

# 每個 NUMA node 分到幾個 rank

| 綁法 | 網卡側 node 0–3 | 遠端 node 4–7 |
| --- | --- | --- |
| 天真綁核 | node 0 有 8 個 | node 4 有 8 個 |
| 分散到 8 個 node | 每個 2 個 | 每個 2 個 |
| 網卡側分散 | 每個 4 個 | 0 個 |
| 遠端分散 | 0 個 | 每個 4 個 |
| 擠到網卡旁 | node 1 有 14 個，node 2 有 2 個 | 0 個 |

::note::
每台 16 個 rank。

落點都由煙霧測試實際取樣確認。

天真綁核的每個 rank 只綁 1 顆 CPU。

# 每組比較只差一個因素

| 比較 | 只差 | 回答的問題 |
| --- | --- | --- |
| 網卡側分散 vs 遠端分散 | 離網卡遠近 | 靠近網卡有沒有用 |
| 網卡側分散 vs 擠到網卡旁 | 分散或擠 | 擠在一起有多傷 |
| 四種固定規則 vs 綁在原地 | 規則或觀察 | 簡單規則夠不夠 |
| 每種綁法 vs 預設不綁 | 綁或不綁 | 收益有多大 |

::note::
四種固定規則：天真綁核、分散到 8 個 node、網卡側分散、遠端分散。

網卡側分散 vs 分散到 8 個 node 同時差兩個因素，只列出、不下結論。

# 次數與長時間執行

| 項目 | 內容 |
| --- | --- |
| 短版 | 每種綁法、每個程式各 10 次 |
| 長版長度 | 4 倍長與 30 s 以上，各 5 次 |
| 長版程式 | BT、MG、allreduce、alltoall |
| 長版綁法 | 預設不綁、綁在原地、最快的固定規則 |
| 長版總數 | 105 次 |

::note::
長版用來拆開固定成本與每次迭代的時間。

LU 在第一段沒有空間，不做長版。

最快的固定規則由短版的中位數決定，規則事先寫死。

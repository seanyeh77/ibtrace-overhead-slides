# 就地校準：在同一組節點上量懲罰

| 步驟 | 做什麼 |
| --- | --- |
| 1 | 程式結束後，用程式自己的訊息大小重放一小段 |
| 2 | 在受影響的路徑上量一次 |
| 3 | 在對照路徑上量一次 |
| 4 | 每則訊息的懲罰 = 受影響 − 對照 |

# schedstat：作業系統記錄每個執行緒的排隊時間

| 欄位 | 意思 |
| --- | --- |
| 在 CPU 上的時間 | 程式真的在執行 |
| **排隊等 CPU 的時間** | 已經準備好，但 CPU 被別人佔著 |
| 被排上 CPU 的次數 | 切換的次數 |

# 定版時的已知限制

| 限制 | 影響 |
| --- | --- |
| 找不到乾淨的對照網卡 | 競爭流量不預測，算 0 ms |
| 小訊息一則一則累加懲罰 | 4 KiB allreduce 高估 |
| 校準只量 5 次取中位數 | 沒有檢查雜訊大小 |
| 排隊時間全部算被搶 | 可能把正常的排程也算進去 |
| 校準只配對下一個節點 | 流量主要給別人時，可能不具代表性 |

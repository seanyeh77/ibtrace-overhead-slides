# 就地校準：在同一組節點上量懲罰

| 步驟 | 做什麼 |
| --- | --- |
| 1 | 程式結束後，用程式自己的訊息大小重放一小段 |
| 2 | 在受影響的路徑上量一次 |
| 3 | 在對照路徑上量一次 |
| 4 | 每則訊息的懲罰 = 受影響 − 對照 |

對照路徑：同一張網卡、沒有外來流量的網卡，或 CPU 綁在網卡那一側。

找不到乾淨的對照時，這一類就不預測。

校準不算進程式的時間，每次約 17 s（中位數）。

# 就地校準的例子：alltoall 64 KiB 的競爭流量

| 做法 | 每則訊息的懲罰 | 預測 ΔT | 實測 ΔT |
| --- | ---: | ---: | ---: |
| 第二版：外部常數 | 依流量查表 | +73.3 ms | +99.1 ms |
| 第三版：就地校準 | 15.0 µs | +108.2 ms | +99.1 ms |

資料是 4 個節點 × 4 個 rank（開發資料）。

外部常數來自量延遲的小型測試，低估了懲罰。

在同一組節點上直接量，誤差從 25.8 ms 降到 9.1 ms。

# schedstat：作業系統記錄每個執行緒的排隊時間

| 欄位 | 意思 |
| --- | --- |
| 在 CPU 上的時間 | 程式真的在執行 |
| **排隊等 CPU 的時間** | 已經準備好，但 CPU 被別人佔著 |
| 被排上 CPU 的次數 | 切換的次數 |

檔案是 /proc/&lt;pid&gt;/task/&lt;tid&gt;/schedstat。

ibmon 每 1 ms 讀一次，前後相減。

第二欄就是「被搶」的時間，不用再從空檔猜。

# 分辨計算與被搶：miniFE 搶 CPU

| 項目 | 有忙迴圈 | 沒有忙迴圈 |
| --- | ---: | ---: |
| rank 1 呼叫之間的空檔 | 1,652 ms | 823 ms |

| 做法 | 預測 ΔT | 實測 ΔT |
| --- | ---: | ---: |
| 第二版：空檔比中位數長就算停頓 | +1,850 ms | +984 ms |
| 第三版：只算排隊等 CPU 的時間 | +975 ms | +984 ms |

沒有忙迴圈時，空檔也有 823 ms，那是正常的計算。

第二版把它也算成停頓，所以高估將近一倍。

# 讀 schedstat 不改變 ΔT 的結論

| 取樣間隔 | 第 1 輪 | 第 2 輪 | 第 3 輪 |
| --- | ---: | ---: | ---: |
| 1 ms | 0.98 倍 | 1.02 倍 | 1.02 倍 |
| 5 ms | 0.95 倍 | 0.98 倍 | 1.16 倍 |
| 10 ms | 0.90 倍 | 1.04 倍 | 0.92 倍 |

比值 = 開 schedstat 的 ΔT ÷ 不開的 ΔT。

9 個比值的 95 % 區間都含 1 倍（job 604682，360 次執行）。

所以第三版用 1 ms 取樣。

# 一個 rank 放錯 NUMA：預測不再是 0 ms

| 放法 | 實測 ΔT | 第二版 | 第三版 |
| --- | ---: | ---: | ---: |
| 只有一個 rank 在另一側 | +0.50 ms | 0 ms | +0.55 ms |
| 兩個 rank 的 CPU 都在另一側 | +0.23 ms | +0.55 ms | +0.55 ms |

第二版只把懲罰加在放錯的 rank 上。

放錯的 rank 從來不是最慢的，所以預測是 0 ms。

第三版把懲罰算成傳輸的成本，等它的 rank 也算進去。

資料是 4 MiB allreduce，各跑 10 次（job 601387）。

# 每節點 4 個 rank：差異從哪裡來

| 組 | 實測 ΔT | 第三版 | 第二版 | 原因 |
| --- | ---: | ---: | ---: | --- |
| alltoall 64 KiB 競爭流量 | +99.1 ms | +108.2 ms | +73.3 ms | 校準較準 |
| 同上，沒有乾淨的對照網卡 | +99.2 ms | 0 ms | +56.3 ms | 不預測，算 0 ms |
| alltoall 64 KiB 多開 rail | −5.6 ms | +1.7 ms | −2.9 ms | 校準說 8 條較快 |
| allreduce 64 KiB 競爭流量 | +16.1 ms | +172.6 ms | +104.1 ms | 兩版都高估 |

方向錯的 3 組中，2 組是「不預測」，1 組是多開 rail。

# 定版時的已知限制

| 限制 | 影響 |
| --- | --- |
| 找不到乾淨的對照網卡 | 競爭流量不預測，算 0 ms |
| 小訊息一則一則累加懲罰 | 4 KiB allreduce 高估 |
| 校準只量 5 次取中位數 | 沒有檢查雜訊大小 |
| 排隊時間全部算被搶 | 可能把正常的排程也算進去 |
| 校準只配對下一個節點 | 流量主要給別人時，可能不具代表性 |

這些限制在看到評估資料之前就寫下了。

# 評估方式的修正

| 第三版評估的問題 | 第四版的做法 |
| --- | --- |
| 背景流量提早啟動，T 變短 | 每個狀態啟動前都等 3 s |
| 對照組偏離 0 也照樣計分 | 對照組的區間不含 0 時，先停下檢查 |
| 每次執行只有 1–2 s | 加一組 30 s 以上的執行 |

]" />

# 跨 NUMA 實驗：只換網卡的位置

| 每次迭代的時間（4×4） | 2 條同側 | 4 條同側 | 4 條混合 | 8 條 |
| --- | ---: | ---: | ---: | ---: |
| allgather 256 KiB | 147.8 µs | **112.6 µs** | 181.0 µs | 177.0 µs |
| alltoall 1 MiB | 581.4 µs | **515.9 µs** | 720.9 µs | 725.8 µs |

::note::

<Note :notes="[
  ['每個節點有 8 張網卡。', '兩顆 CPU 旁邊各接 4 張。', '同側：只用自己這顆 CPU 的卡。', '4 條混合：2 張同側、2 張對側。', 'rail 數和 4 條同側一樣。', '結果和 8 條一樣慢。', '損失來自對側的網卡。', '不是 rail 數本身。', '資料來自 job 614813。'],
]" />

# 目前方法最大的盲點

| 問題 | 現況 |
| --- | --- |
| 點對點的校準 | 量不到 16 個 rank 同時做 collective 的效果 |
| 原因 | 多個 rank 同時用對側 NUMA 的網卡 |
| LAMMPS 的迴圈 | 30 次開 tracer 的執行都沒有對齊 |

::note::

<Note :notes="[
  ['校準要改成 16 個 rank 同時跑。', '才量得到跨 NUMA 的效果。', '研究 rail 需要每個節點有多張網卡。', '其他類別可以移到國網的 CPU 叢集。'],
]" />

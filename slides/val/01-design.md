# 一組 = 程式 × 瓶頸 × 動作

| 一組的組成 | 例子 |
| --- | --- |
| 程式 | NPB BT |
| 瓶頸 | 網卡設定（每個 rank 用全部 8 張卡） |
| 動作 | 改成只用同側 4 張卡 |
| 實測 ΔT | +626.41 ms |
| 預測 ΔT | +501.49 ms |

每一組只比較兩個數：實測 ΔT 與預測 ΔT。

ΔT 是正的，代表做了動作之後變快。

# 三個測試程式：開發時完全沒有跑過

| 程式 | 在算什麼 | 通訊的樣子 | 問題大小 | 一次多久 |
| --- | --- | --- | --- | ---: |
| MG class B | 多重網格解 Poisson | 大小訊息混雜 | 256³，20 次迭代 | 約 1.0 s |
| LU class A | SSOR 解 Navier-Stokes | 大量小訊息 | 64³，250 次迭代 | 約 2.3 s |
| BT class A | ADI 解 Navier-Stokes | 大塊邊界資料 | 64³，200 次迭代 | 約 2.9 s |

三個都來自 NPB，是 NASA 的平行運算標準測試。

class 是問題大小，依試跑的時間與 ring 用量決定。

# 每個程式五種情境，各有注入與移除

| 情境 | 注入狀態 | 移除狀態 | 作用在 |
| --- | --- | --- | --- |
| 搶 CPU | 忙迴圈和程式同一個核心 | 忙迴圈改到隔壁核心 | rank 1 |
| NUMA 錯置 | 程式綁到網卡對側 | 綁回網卡同側 | rank 1 |
| 外來流量 | 對程式的卡灌 391 Gb/s | 不灌流量 | rank 1 的卡 |
| 網卡設定 | 每個 rank 用 8 張卡 | 同側 4 張或同側 2 張 | 全部 16 個 rank |
| 對照組 | 流量灌在程式沒用的卡 | 不灌流量 | 程式沒用的卡 |

全部只用一般使用者的權限。

# 兩個狀態之間只差有沒有瓶頸

| 固定的條件 | 值 |
| --- | --- |
| 節點 | 同一個 job 的 4 個節點，健康檢查 99 項全過 |
| 配置 | 4 節點 × 每節點 4 rank = 16 rank |
| 程式的輸入 | 同一個 class，同樣的迭代次數 |
| 啟動前等待 | 每個狀態都等 3.0 s，實測 2.99–3.08 s |
| 執行順序 | 429 次執行以固定種子打亂 |
| 模型與計分 | 收資料前凍結並 commit |

# 每個狀態跑 13 次，共 429 次

| 執行 | 次數 | 用途 |
| --- | ---: | --- |
| 不開 tracer | 10 次 | 算實測 ΔT，也就是答案 |
| 開 tracer | 3 次 | 給模型讀，產生預測 |

| 規模 | 數量 |
| --- | ---: |
| 狀態 | 3 個程式 × 11 個 = 33 個 |
| 執行 | 33 個 × 13 次 = 429 次，全部有效 |
| 計分的組 | 3 個程式 × 6 組 = 18 組 |

網卡設定有兩種動作，所以每個程式有 6 組。

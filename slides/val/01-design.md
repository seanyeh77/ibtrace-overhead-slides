# 一組 = 程式 × 瓶頸 × 動作

| 一組的組成 | 例子 |
| --- | --- |
| 程式 | NPB BT |
| 瓶頸 | 網卡設定（每個 rank 用全部 8 張卡） |
| 動作 | 改成只用同側 4 張卡 |
| 實測 ΔT | +626.41 ms |
| 預測 ΔT | +501.49 ms |

每一組只比較兩個數：實測 ΔT 與預測 ΔT。

ΔT 是正的，代表做了動作之後變快。

# 網格大小決定計算量，也決定通訊量

| 名詞 | 意思 |
| --- | --- |
| 網格 | 把模擬的空間切成很多小格，每格存一組數值 |
| 64³ | 每邊 64 格，共 262,144 格 |
| 迭代 | 把所有格更新一次，就是一次迭代 |
| 切塊 | 平行時，每個 rank 負責其中一塊 |
| 交換邊界 | 算邊緣的格子，需要鄰居那一側的值 |

每次迭代都要交換邊界，這就是網路通訊。

迭代一次就是主迴圈的一圈。

# 測試程式來自 NPB：NASA 的平行運算標準測試

| 程式 | 模擬什麼 | 怎麼解 |
| --- | --- | --- |
| MG | 3D 空間中的位勢分布 | 多重網格法：粗細網格來回修正 |
| LU | 3D 流體的流動 | SSOR 法：一層一層往前推 |
| BT | 3D 流體的流動 | ADI 法：x、y、z 三個方向輪流解 |

三個程式都是點對點通訊為主。

它們的訊息大小與節奏各不相同。

# MG：同時用粗網格與細網格

| 項目 | 說明 |
| --- | --- |
| 做法 | 先在細網格算，再到粗網格修正大範圍的誤差 |
| 每次迭代 | 從最細一路縮到最粗，再一路放回最細 |
| 通訊 | 每一層都和鄰居交換邊界 |
| 訊息大小 | 細網格的邊界大，粗網格的邊界小 |
| 對工具的考驗 | 大小訊息混雜，主迴圈裡的呼叫很多樣 |

# LU：像波浪一樣一層一層推進

| 項目 | 說明 |
| --- | --- |
| 做法 | 每一格要用到上游格子剛算好的值 |
| 平行方式 | rank 要等上游的 rank 算完，才能開始算 |
| 通訊 | 算完一小段，就把結果傳給下游 |
| 訊息大小 | 很小，但數量非常多 |
| 對工具的考驗 | 大量小訊息，rank 之間彼此等待 |

# BT：x、y、z 三個方向輪流解

| 項目 | 說明 |
| --- | --- |
| 做法 | 每一步沿 x、y、z 方向各解一次方程組 |
| 方程組的形狀 | 區塊三對角，每格是一個 5 × 5 的區塊 |
| 通訊 | 每個方向都要和鄰居交換整個面 |
| 訊息大小 | 大塊的邊界資料，比 LU 大很多 |
| 對工具的考驗 | 大訊息讓網卡設定的影響特別明顯 |

# class 依試跑決定：先跑 class B，太長就降一級

| 規則 | 內容 |
| --- | --- |
| 目標 | 一次執行約 1–2 s，429 次的總成本才可控 |
| 試跑 | 三個程式都先跑 class B，不開與開 tracer 各 1 次 |
| 降級 | 不開 tracer 超過 5 s，就降一級 |
| 只看 | 時間、是否成功、ring 用量，不看任何 ΔT |

| 程式 | class B 試跑 | 決定 | 理由 |
| --- | ---: | --- | --- |
| MG | 0.97 s | class B | 不到 5 s；class A 只有 4 次迭代，找不到主迴圈 |
| LU | 6.99 s | class A | 超過 5 s，降一級 |
| BT | 9.47 s | class A | 超過 5 s，降一級 |

# 每個程式五種情境，各有注入與移除

| 情境 | 注入狀態 | 移除狀態 | 作用在 |
| --- | --- | --- | --- |
| 搶 CPU | 忙迴圈和程式同一個核心 | 忙迴圈改到隔壁核心 | rank 1 |
| NUMA 錯置 | 程式綁到網卡對側 | 綁回網卡同側 | rank 1 |
| 外來流量 | 對程式的卡灌 391 Gb/s | 不灌流量 | rank 1 的卡 |
| 網卡設定 | 每個 rank 用 8 張卡 | 同側 4 張或同側 2 張 | 全部 16 個 rank |
| 對照組 | 流量灌在程式沒用的卡 | 不灌流量 | 程式沒用的卡 |

全部只用一般使用者的權限。

# 兩個狀態之間只差有沒有瓶頸

| 固定的條件 | 值 |
| --- | --- |
| 節點 | 同一個 job 的 4 個節點，健康檢查 99 項全過 |
| 配置 | 4 節點 × 每節點 4 rank = 16 rank |
| 程式的輸入 | 同一個 class，同樣的迭代次數 |
| 啟動前等待 | 每個狀態都等 3.0 s，實測 2.99–3.08 s |
| 執行順序 | 429 次執行以固定種子打亂 |
| 模型與計分 | 收資料前凍結並 commit |

# 每個狀態跑 13 次，共 429 次

| 執行 | 次數 | 用途 |
| --- | ---: | --- |
| 不開 tracer | 10 次 | 算實測 ΔT，也就是答案 |
| 開 tracer | 3 次 | 給模型讀，產生預測 |

| 規模 | 數量 |
| --- | ---: |
| 狀態 | 3 個程式 × 11 個 = 33 個 |
| 執行 | 33 個 × 13 次 = 429 次，全部有效 |
| 計分的組 | 3 個程式 × 6 組 = 18 組 |

網卡設定有兩種動作，所以每個程式有 6 組。

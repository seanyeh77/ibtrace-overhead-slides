# T 量的是整個程式，扣掉啟動的等待

| 問題 | 做法 |
| --- | --- |
| 時間從哪裡來 | 每個 rank 的 `rank<N>.json` 記開始與結束 |
| 量的範圍 | 從程式啟動到程式結束，含初始化與收尾 |
| 為什麼不從最早開始 | srun 啟動有先後，先到的 rank 只是在等 |
| 為什麼算到最晚結束 | 最後一個 rank 做完，程式才算結束 |
| 為什麼不用程式印的時間 | 每個程式印的範圍不同，無法比較 |

# 實測 ΔT = 兩個狀態的中位數相減

| 步驟 | BT：8 張 → 同側 4 張 |
| --- | ---: |
| 注入狀態，10 次 T 的中位數 | 3,732.23 ms |
| 移除狀態，10 次 T 的中位數 | 3,105.81 ms |
| 實測 ΔT | +626.41 ms |
| 95 % 區間（bootstrap 10,000 次） | +532.08 ~ +704.41 ms |

用中位數，偶發的一次慢執行不會影響結果。

區間不含 0，才能確定真的變快或變慢。

# 對照組：不該變慢的情境要量到 0

| 程式 | 對照組 ΔT | 95 % 區間 | 結果 |
| --- | ---: | ---: | --- |
| MG | −10.69 ms | −50.68 ~ +14.53 ms | 含 0，通過 |
| LU | +4.10 ms | −18.53 ~ +41.67 ms | 含 0，通過 |
| BT | +4.52 ms | −34.77 ~ +47.02 ms | 含 0，通過 |

區間不含 0 時，代表環境有偏差，就停下不計分。

# 健康檢查：每個 job 先檢查節點

| 檢查 | 這次的結果 | 門檻 |
| --- | ---: | ---: |
| 8 B 延遲 | 1.90–2.62 µs | ≤ 2.85 µs |
| 每張卡的頻寬 | 365.5–367.9 Gb/s | ≥ 329.4 Gb/s |
| 兩節點 alltoall 1 MiB，8 張卡 | 59.0–63.4 µs | ≤ 75.6 µs |
| 每個節點的 1 MiB 傳輸 | 6.03–6.06 µs | ≤ 7.25 µs |

任一項不合格，整個 job 作廢，換節點重送。

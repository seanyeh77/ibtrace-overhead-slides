# 誤差：換成移除狀態 T 的百分點

| 項目 | BT：8 張 → 同側 4 張 |
| --- | ---: |
| 預測 ΔT | +501.49 ms |
| 實測 ΔT | +626.41 ms |
| 移除狀態的 T 中位數 | 3,105.81 ms |
| 誤差 = 100 × (預測 − 實測) ÷ T | −4.02 百分點 |

換成百分點，不同長度的程式才能一起平均。

18 組的絕對值取平均，就是 MAE。

# 方向：只算實測確定變快或變慢的組

| 規則 | 內容 |
| --- | --- |
| 計入的組 | 實測區間不含 0，共 10 組 |
| 算對 | 預測不是 0，而且和實測同號 |
| 算錯 | 預測是 0，或和實測異號 |
| 本研究的分母 | 10 組 − 出錯的 2 組 = 8 組 |

10 組是三個程式的搶 CPU、兩種網卡設定，加上 LU 的 NUMA 錯置。

# 兩種排第一：每份 trace 各算一次

| 指標 | 問的問題 | 分母 |
| --- | --- | --- |
| 實測最佳排第一 | 第一名是實際最有效的動作嗎 | 6 個狀態 × 3 份 = 18 份 |
| 注入的瓶頸排第一 | 第一名是放進去的瓶頸嗎 | 12 個狀態 × 3 份 = 36 份 |

實測最佳要區間下界大於 0，才算數。

本研究在 LU 網卡設定出錯 3 份，分母變成 15 與 33。

# 照實記錄的問題，不從資料中排除

| 問題 | 影響 |
| --- | --- |
| MG 的主迴圈沒有對齊 | 網卡設定 2 組記為 0 ms |
| LU 的重播校準失敗 | 60 次啟動全部 MPI_ERR_TRUNCATE |
| LU 模型出錯 | 網卡設定 2 組不計入，3 份 trace 不計入 |
| 出錯的 2 組若記為 0 ms | MAE 約 8.65 百分點 |
| 看到結果之後 | 沒有改模型、規則或程式，也沒有重跑 |
